## 二、失败原因归类（按现象合并）

| 原因 | 涉及条目 | 说明 |
|---|---|---|
| **A. 该内容本来就没有视频** | 1、3（存疑）、4、5、6、7、10 | yt-dlp 的 `WeiboIE` / `WeiboVideoIE` **只产出视频格式**。图文、图集、实况图、动图、头条文章这些没有独立视频流，于是报 `No video formats found!`。这不是「站点改版」，而是**这条链路本身只覆盖视频**。 |
| **B. 需要微博的「访客系统」** | 1、4、5、6、7、10、11、12（大概率全部） | 实测 `m.weibo.cn/api/statuses/show?id=<id>` 与 `m.weibo.cn/detail/<id>` 都返回 **`Sina Visitor System`** 验证页，而不是数据。微博会先把匿名访问者送进访客验证，拿到票据后才给内容。 |
| **C. 头条文章是另一种页面类型** | 11、12 | `weibo.com/ttarticle/x/m/show#/id=...` 是**头条文章**（图文长文），不是微博正文；且 ID 是 `#` 后面的片段，服务端根本收不到。yt-dlp 没有任何提取器认这个形态。 |
| **D. 音视频分轨 + 下载未落地** | 8 | 解析出来的流是「音频、视频分开」的（`该站点是音视频分轨流` 是应用里已有的提示）；下载后没有可播放文件、相册里也没有新文件 —— **下载/合流环节有 bug**，需要单独查。 |
| **E. 音频播放器没有进度条** | 9 | 播放器 UI 只按视频设计，纯音频时没有可拖动的进度条。 |

## 三、已核实的取证（不是推测）

### 3.1 失败条目真的被「访客系统」拦住了

```
GET https://m.weibo.cn/api/statuses/show?id=5354751199543635
→ HTTP 200，返回 9690 字节的 HTML
→ <title>Sina Visitor System</title>        ← 不是 JSON，是访客验证页

GET https://m.weibo.cn/detail/5354751199543635
→ 同样返回 <title>Sina Visitor System</title>

GET https://weibo.com/ajax/statuses/show?id=5354751199543635
→ HTTP 403
```

### 3.2 纯协议拿访客票据：目前走不通

按公开的访客流程试了一遍：

```
POST https://passport.weibo.com/visitor/genvisitor2  → retcode 20000000（成功）
POST https://passport.weibo.com/visitor/visitor?a=incognito → 拿到 cookie: SRF/SRT/SUB/SUBP/SVB
再请求 m.weibo.cn/api/statuses/show?id=... → **仍然返回 Sina Visitor System**
```

即：能拿到访客 cookie，但**接口仍然要求走页面的 JS 验证**，纯 HTTP 复现不了。这条路要么继续深挖（成本高、随时变），要么改用下面这条。

### 3.3 可行的替代路径（与小红书同一套思路）

**用应用内 WebView 打开 `https://m.weibo.cn/detail/<id>`**：真实的 Chromium 环境会自动完成访客验证，页面里带着结构化数据（微博移动版是服务端渲染，`$render_data`）。这样：

- 不需要用户登录微博；
- 图文 / 图集 / 实况图 / 动图 / 混排都能从同一份页面数据里取；
- 视频类仍可保留现在能用的 yt-dlp 快路径（已验证 3/3 通过）；
- 头条文章（`ttarticle`）是另一类页面，要单独判断。

## 四、结论与建议的处理顺序

1. **先修「能用但坏了」的两条**（成本最低、用户感知最强）：
   - 第 8 条：音频视频分轨的**下载/合流 bug**（下载后无文件、相册也看不到）；
   - 第 9 条：纯音频预览的**进度条**。
2. **再做微博的自建取数链路**（WebView 读 `m.weibo.cn/detail/<id>`），覆盖图文 / 图集 / 实况图 / 动图 / 混排。
3. **最后处理头条文章**（`ttarticle` 是独立页面类型，需要单独解析）。
4. 视频类保持现状（yt-dlp 已验证可用）。
5. 失败文案要改：现在统一显示「该站点可能改版了」，对「本来就没有视频」的内容是误导 —— 应改成「这条微博没有视频，当前只支持视频」。

### 6.1 微博链路最终形态

- **视频类**：首次仍交给 yt-dlp（快、无需 WebView）；报 `No video formats found!` 时自动回落到 WebView。
- **图文 / 图集 / 实况图 / 动图 / 混排**：直接走 WebView 读页面里的 `$render_data.status`，动效地址取 `pics[i].videoSrc`。
- **头条文章**：识别 `ttarticle` 或 `card.weibo.com/article`，取 `#/id=` 后的数字，打开文章页后先滚两次屏触发图片懒加载，再取标题与图片。
- 微博全程**不需要登录、不需要 Cookie**。

### 6.2 仍未覆盖

- **`t.cn` 短链**：本期**故意没有识别**。`t.cn` 是新浪通用短链域名，链接里不含 `weibo` 字样，现有平台识别规则认不出来，会提示「不支持这种链接」；且短链必须先发一次网络请求拿到跳转后的真实地址，再判断它到底指向微博、文章还是别的新浪业务。用户目前找不到微博分享出 `t.cn` 短链的场景，所以本期不做，留作已知限制。
- **`m.weibo.cn/c/wbox?id=...` 卡片页**（第 11 条）：不是标准微博正文，也不是头条文章，暂不解析。

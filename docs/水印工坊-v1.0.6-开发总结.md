## 一、按时间顺序的开发记录

### 1. 一机一码授权（已完成并真机验证）

**需求**：用户不会主动发设备码，软件必须自己识别设备；前 3 次免费，之后锁定。

**方案**：Cloudflare Workers + KV，单文件 `server/worker.js`。

- 密钥格式 `WM-XXXX-XXXX-XXXX`（Crockford Base32，12 位）
- 设备码 = `SHA-256("wm-license-v1|ANDROID_ID|厂商|品牌|型号|设备名")` 前 32 位
- 服务端用 `LICENSE_SECRET` 做 HMAC，签发 30 天 token；`ADMIN_TOKEN` 管理口令
- 客户端：试用 3 次 → 第 4 次拦截；激活后离线可用（token 本地保存）

**验证**：服务端 14 项测试通过；真机验证「3 次试用→第 4 次拦截→激活成功→重启保持→停用提示→解绑恢复→长按版本号重置」。

**部署**：`https://watermark-license.xiayuyang750.workers.dev`。

### 2. Cloudflare 国内可达性与 VPN 提示（已完成）

`*.workers.dev` 国内无法直连，免费域名（us.kg / dpdns.org / xx.kg / qd.je）注册全部失败。最终在产品内如实说明，并在设置页提供加速器下载入口。

**入口调整**：最初指向 GitHub Release，考虑到大陆网络访问 GitHub 不稳定，改为**蓝奏云分享页 + 提取码**，浏览器可直接下载。

### 3. 第三方 APK 静态安全分析（已完成）

对 `雷霆加速器.apk` 做归档清单、DEX 指令级归属与原生库字符串分析，产出 `docs/雷霆加速器-静态分析报告.md`，结论：**未发现恶意代码**。

### 4. 抖音：接口忽略 aweme_id 的修复（已完成）

**症状**：部分视频解析失败，或解析出完全无关、每次不同的视频。

**根因**：`aweme/v1/feed` 是推荐流接口，缺 App 公共参数时会对部分作品忽略 `aweme_id`，只回推荐流。

**修复**：补上 `DOUYIN_COMMON_PARAMS`（aid / device_platform / version_code 等公开客户端参数，不含密钥）。A/B 实测：不带参数 0/5 命中，带参数 4/4 命中；修复后同一链接两次解析 MD5 一致。

### 5. 微博接入与多内容形态（已完成）

**链路**：
- 视频页（`video.weibo.com/show`、`weibo.com/tv/show`）→ yt-dlp
- 正文类（`weibo.com/<uid>/<mid>`、`/detail/<mid>`）→ **新增内置浏览器（WebView）读取 `$render_data.status`**
- 头条文章（`ttarticle`、`card.weibo.com/article`）→ 浏览器 + 滚屏触发懒加载

**为什么正文类要新增 WebView**：yt-dlp 只覆盖视频页，遇到图文/图集会误判甚至直接报错；而且用户复制到的往往是**正文链接**，真正的视频链接藏在正文里（`video.weibo.com/show?fid=...`）。走浏览器后，既能把图文/图集/实况/动图读准，也能从正文里捞出 `fid` 再重定向到视频页解析 —— 长视频不再因为「贴的是正文链接」而解析不到。

**覆盖形态**（12 条真实链接实测）：视频、图文、图集、实况图、超话实况、动图合集、混排、头条文章、长视频、音频、实况图合集。

**修复**：
- 图片全量 403 → `*.sinaimg.cn` 防盗链，必须带 `Referer: https://weibo.com/`
- 音频无进度条/无暂停键 → 用 `onTracksChanged` 的真实轨道判定纯音频
- 长视频/合集帖报 `Extractor failed to obtain "id"` → 正文类浏览器优先 + 正文里捞 `fid` 重定向
- **实况图合集被误判成「音视频分轨」** → 走浏览器读页面数据后按 `pics` 还原实况，预览与下载恢复正常

**性能说明**：微博头条文章的图片是**冷加载**（滚动到可视区域才请求），应用必须完整读完正文才能拿到全部媒体，因此这类链接会比普通微博多 2~3 秒。这是平台机制决定的，不是解析器卡住。

**已知限制**：`t.cn` 短链（新浪通用短链，未识别）、`m.weibo.cn/c/wbox` 卡片页。

### 6. 小红书（已完成）

**链路**：应用内置浏览器，首次需登录一次（登录态留在应用内），不导出 Cookie。

**覆盖**：视频、图文、图集、实况图；实况图图片与动效视频同名配对。

**代价**：小红书限制同时在线设备，应用内登录会把电脑网页版挤下线。

**本轮修复（分辨率 0×0 / 参数丢失）**：
- 现象：小红书图片/实况图在相册显示 0×0，且参数面板空白。
- 根因：小红书 CDN 实际下发 WebP，但地址无扩展名，落盘成 `.jpg`；相册按扩展名解析失败。
- 修复：下载后按文件头改真实扩展名（`.webp`）；随后发现相册只对真 JPEG 同时读取分辨率与 EXIF，最终在下载完成、通知相册前把 WebP 转成 JPEG（质量 95），并复制 25 个 EXIF 字段（机型、镜头、ISO、快门、光圈等）。
- 实测：转换后 1080×1440、Make=Apple、Model=iPhone 15 Pro、ISO=200 全部保留；MediaStore 记录为 `image/jpeg`。

### 7. 微信公众号 / 图文贴图（本轮新增，已完成）

**两套模板**（都在 `mp.weixin.qq.com/s/<id>`）：
- 文章模板：正文容器 `id="js_content"`，标题 `msg_title`，作者 `nickname`
- 贴图/图文模板：数据在 `picture_page_info_list`，标题取 `og:title`，作者取 `nick_name`

**关键点**：
- 判分支必须先看 `js_content`：文章页里也内嵌了 `picture_page_info_list` 的模板代码（实测 8 处），只按它判断会走错。
- 图片：正文 `<img data-src>`，路径末段尺寸号换成 `/0` 提质量；贴图优先 `original_info`（查看原图）。
- 视频：`mp_video_trans_info` 给 4 档，直链在 `mpvideo.qpic.cn`。
- 直链短时有效（`dis_t` = 页面加载时刻），下载前自动重新抓页面换新地址。
- CDN 同时校验 UA：ExoPlayer 默认 UA / 空 UA / 安卓 Chrome UA 会 403；必须用微信 UA + Referer。
- 正文展示：默认折 4 行，可展开/收起、复制；纯文字文章也能读正文，只是没有下载按钮。

**「图文 + 视频」混合作品里，视频偶发无法预览（已修）**：

- 症状：图片正常，点视频却是黑框、0:00；偶尔重新解析又能播；下载也时成时败。
- 根因有两层：
  1. **`mpvideo.qpic.cn` 同时校验 Referer 与 User-Agent**。实测：微信 UA、桌面 Chrome UA 返回 200；ExoPlayer 默认 UA、空 UA、安卓 Chrome UA 全部 403。播放器拿不到数据，表现就是黑屏 + 时长 0。
  2. **视频直链是页面现签发的**（`dis_t` 等于页面加载时刻），存进历史库后过一阵就失效；再播放/再下载用的是旧地址，于是 403 —— 这就是「有时成功、有时失败、过会儿又变回去」。
- 处理：
  - 播放器对 `mpvideo.qpic.cn` 单独设置 `User-Agent = 微信 UA` + `Referer: https://mp.weixin.qq.com/`（`dataSourceFactory`）。
  - 下载前重新抓一次文章页，把媒体列表/直链换成新地址并写回历史库（`_refresh_wechat_rec`）。
  - 图片（`mmbiz.qpic.cn`）不需要 Referer，保持不加头，避免微博/小红书那种「带错 Referer 反而 403」的坑。

**实测**：4 条链接（多图文章 / 视频图文 / 看一看图文 / 服务号贴图）全部通过；贴图原图单张 8.47MB；文章视频 1920×1080 3.4MB 可下载。

### 8. 微信视频号（本轮新增，仅能预览）

**发现**：
- `weixin.qq.com/sph/<id>` 302 到 `channels.weixin.qq.com/finder-preview/...`，页面是 JS 壳，数据依赖 `WeixinJSBridge`。
- 但预览页会调一个**公开、无需登录**的接口：

  ```
  POST https://channels.weixin.qq.com/finder-preview/api/feed/get_feed_info
  {"baseReq":{"generalToken":""},"shortUri":"<id>"}
  ```

  返回标题、作者、封面、发布时间、点赞数；**没有视频地址**（`h264VideoInfo` / `videoUrl` 被服务端按登录态掐掉）。

**产品处理**：识别链接 → 展示预览卡片 → 明确提示「不支持直接下载」。微信客户端通常也没有「保存视频」入口。

### 9. 抖音平台链接发放规则改版：图文被误当视频（本轮修复两轮）

**性质**：平台侧改版（作品链接与接口返回结构变化），不是客户端主动改动。

**症状**：所有图文 / 图集 / 实况图突然变成「视频」——黑屏有声、时长 0、下载到音频、相册看不到。

**根因（抓接口确认）**：抖音 feed 接口开始返回图文作品，且 `video` 只剩 BGM 占位：

```
aweme_type = 68
images = [...]
video.duration = 0
video.play_addr = https://v5-ex-music.douyinstatic.com/...   ← 音频
```

**第一轮修复**：解析时先看 `images`，有图就走图集分支；图片取 `url_list`（无水印），实况动效取 `images[i].video.play_addr`。

**第二轮修复（实况仍异常）**：
- 单张实况：接口只有静态图，`is_live_photo=1` 但动效地址不存在。
- 实况合集：接口连 `is_live_photo` 都没有，数据与普通图集完全一致。
- 结论：**接口无法可靠区分普通图集与实况合集**，只有页面 SSR 数据里有 `playAddr`。
- 最终策略：**只有「每张图都带动效地址」的内容才走接口**（有声图集），其余图片内容（普通图集、单张实况、实况合集）一律回退 WebView —— 恢复事件前的链路。

**实测**：有声图集 13/11 张全部还原；图集、单张实况、实况合集均正确回退。

## 三、未完成任务

### 3.1 快手平台
尚未开始。需要先确认：分享链接形态、是否需要登录/签名、图文/视频分别走哪条链路。

### 3.2 「平台 × 内容形态」补测
- B站 / YouTube / TikTok / Instagram 的图文、图集、多图、混排等形态尚未逐条测试。
- 微博：`t.cn` 短链、`m.weibo.cn/c/wbox` 卡片页。
- 微信视频号：视频流无法获取（平台硬限制）。
- 抖音：单张实况/实况合集依赖 WebView，解析较慢；视频偶发「画面缩左上角」未复现。

### 3.3 支付 SDK 接入
- 当前只有「一机一码」密钥体系（手动发密钥）。
- 尚未接入支付 SDK，也没有「购买 → 自动发密钥」的闭环。
- 需要决定：支付渠道（微信/支付宝/第三方）、订单与密钥的绑定方式、退款与解绑策略、对账与防刷。
- 注意：支付回调需要公网可达的服务端；当前 Cloudflare Workers 国内不可直连，需要额外方案。

### 3.4 全平台正文内容提取
- 目前只有微信公众号会返回正文（`Video.description` + `history.description`）。
- 微博 / 小红书 / 抖音 / X 的解析结果里其实已有原文，但只取了「第一行/截断 120 字」当标题。
- 补齐需要改：各平台解析器 → 数据模型 → 历史库字段 → 解析页正文组件（展开/收起/复制）。
- UI 组件（`BodyBlock`）已经做好，可直接复用。

### 3.5 微博下载提速
- 现状：微博视频走 yt-dlp，实测 10.3 / 14.2 MB/s（波动大）。
- 尝试过把 `weibocdn.com` 加进直链白名单，但实测仍走 `.mp4.part`（yt-dlp 特征），未生效，已回退。
- 需要先解决「如何区分用户是否动过档位」，再决定是否重试。

### 3.6 安全演练报告
- 计划产出「同类下载器如何滥用已授权相册/文件权限」的研究文档 + 用户教育文案。
- 只出文档，不给应用加外发功能。

### 3.7 发布收尾
- 发布说明定稿、GitHub Release 页面、APK 上传。
- 首页/关于页「境外站点需要 VPN」与授权卡片 VPN 说明重复，可合并（低优先级）。

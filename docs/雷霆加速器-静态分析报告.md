## 二、结论分级

### 结论 A：已证实的事实（有字节级证据）

1. **代码来源**：本 App 自身代码位于 `com.leiting.lt1779107724`（466 个类），其中残留 `AngApplication`、`AppConfig$EConfigType`、`V2RayVpnService`（进程名 `:RunSoLibV2RayDaemon`）、`me.dozen.dpreference`、`me.dm7.barcodescanner`、`libv2ray` 等标识 —— 均为开源项目 V2RayNG 的原版特征。原包名 `com.v2ray.ang` 字样已被抹除，但类名残留证明其为**改包重打包**产物。

2. **代理内核**：`libgojni.so`（36 MB）为 **Go 1.25.4** 编译的 V2Ray/Xray Core，含 9628 处 `V2Ray.Core.*` 符号及 vmess / vless / trojan / shadowsocks2022 / geoip / geosite / `refraction-networking/utls`（TLS 指纹伪装）。为**上游原版核心**。

3. **权限清单**（全部 12 项）：
   `ACCESS_NETWORK_STATE`、`CHANGE_NETWORK_STATE`、`INTERNET`、`READ_EXTERNAL_STORAGE`、`CAMERA`、`com.android.vending.BILLING`、`FOREGROUND_SERVICE`、`REQUEST_INSTALL_PACKAGES`、`WRITE_EXTERNAL_STORAGE`、`com.asus.msa.SupplementaryDID.ACCESS`、`freemme.permission.msa`、`WAKE_LOCK`

4. **`CAMERA` 的用途已定位**：`ScannerActivity`、`ScScannerActivity`、`me.dm7.barcodescanner.*`、`com.google.zxing`（266 个类）—— 用于**扫描订阅二维码**，为该类客户端标准功能。

5. **`REQUEST_INSTALL_PACKAGES` 的用途已定位**：仅在 `MainActivity` 中被引用，配合 `installApk`、`update.apk`、`android.intent.action.INSTALL_PACKAGE`、`application/vnd.android.package-archive` —— 为**自更新**流程。
   ⚠️ 且代码中存在 `sig.apkContentsSigners`，即**安装前校验新包签名**，属防御性措施。

6. **设备标识采集**：`com.github.gzuliyujiang.oaid`（开源 OAID 库）+ `repeackage/` 下 35 个 AIDL 桩（华为 / 荣耀 / OPPO / 三星 / 魅族 / 酷派 / 中兴 / Google），用于获取**匿名广告标识 OAID**，属广告归因常规做法。
   注意：清单中**没有 `READ_PHONE_STATE`**，故代码里存在的 `getImei` 无法实际取得 IMEI。

7. **网络端点清单**（DEX 内去重 30 个域名）可分三类：
   - Google 系（广告/服务）：`googleads.g.doubleclick.net`、`googlemobileadssdk.page.link`、`imasdk.googleapis.com`、`adservice.google.com`、`csi.gstatic.com`、`www.googleapis.com` 等
   - 客服 SDK（AIHelp）：`cs30.net`、`aihelp.net`、`proxy.aihelp.net`、`cdn.aihelp.net`；另有 `pv.sohu.com`（城市定位统计）
   - 线路地址：`www.gamestar.live`、`1.2345345.xyz` 及一批 `www.l<随机>.cc:20000` / `www.l<随机>.info:20000`

   内嵌 DNS：`8.8.8.8`、`1.1.1.1`、`223.5.5.5`（公网 DNS）。

8. **客服 SDK 走明文 HTTP**：`http://cs30.net/elva/api/init`、`http://proxy.aihelp.net/elva/api/initset`。且 `network_security_config` 为 `cleartextTrafficPermitted=true`，信任锚同时包含 **`src="system"` 与 `src="user"`**。

9. **`libcryptbox.so`** 导出 `CryptBox.encrypt/decrypt`，内部符号为 `aes_whitebox_encrypt/decrypt_cfb|ctr|ofb` —— **白盒 AES**（用于隐藏自身密钥）。

### 结论 C：无法判定（如实说明）

1. **未做运行时观察**：本报告为纯静态分析，**未运行该 App、未抓取网络流量**。运行时实际发送的数据未验证。
2. **白盒加密导致部分内容不可读**：`libcryptbox.so` 对部分字符串/端点做了白盒 AES 保护，静态无法读取。因此「是否存在隐藏端点」只能在**可读范围内**回答为否。
3. **未联网核查可疑域名归属**：上述 `.cc:20000` / `.xyz` 域名与内嵌 IP `169.44.24.179` / `169.44.24.184` 的注册归属未做联网核验。
4. **自更新通道的性质**：该通道可下发并安装 APK（虽有签名校验）。若其更新服务端被劫持，理论上可推送任意内容 —— 这是**架构层面的信任假设**，非本文件的静态缺陷。

## 三、值得提醒的三点（非恶意，但应知情）

1. **设备标识与广告归因**：会读取 OAID/AAID 并用于广告，符合行业惯例，但确属个人信息范畴。
2. **客服对话走明文 HTTP**：且信任用户自装 CA。含义是客服内容传输未加密，任何装了自签 CA 的环境（公司代理、抓包工具）均可解密其流量。
3. **免费线路为第三方节点**：使用他人节点时，流量经过对方服务器 —— 这是所有免费代理的固有属性，非本 App 独有。

## 五、关于「被网盘判为违规」

**这与文件是否含恶意代码是两个独立问题。**

判为违规的合理解释，是平台内容政策与哈希黑名单层面的机制：

1. 该类代理工具在境内的**公开分发**受限制，网盘普遍按类目/关键词拦截；
2. 此文件的哈希值很可能已进入**共享黑名单** —— 只要有任一平台判定过一次，其他平台按同哈希即拦；
3. 包名、文件名、内置文案中的相关关键词也会参与判定。

因此「被网盘拦」**不能反推**「有木马」。本报告第一节至第四节的全部证据均指向「未发现恶意代码」。

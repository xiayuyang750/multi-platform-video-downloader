# 🎬 水印工坊 v1.0.7 —— 快手入列、实况图能自己合成、解析更快更准

> 安装包见下方 Assets：`shuiyin-gongfang-v1.0.7.apk`

这一版做了四件事：**① 快手正式支持；② 全平台正文提取；③ 新增「实况」页并打通 vivo 实况双写；④ 解析速度与失败判定的一次整体打磨。**

## ✨ 新增

**⚡ 快手** —— 视频、图集、长图图集、单张图片都能拿，走移动端页面直读，**不需要登录、不需要 Cookie、不需要签名**。

- 关键在 UA：桌面 UA 落在 JS 壳页面（零数据），移动 UA 才是服务端直出的完整数据。
- 视频实测 720p 在线播放、1080p 下载；图集按原图逐张落盘（WebP 转真 JPEG，相册分辨率正常）。
- **实况图只拿静态图**：动效不在分享页数据里，App 接口带签名且要过 antispam，第三方小程序走的是「仿冒域名 + COS 中转 + 密文路径」，URL 不可复用。这一点如实标注，不假装支持。

**📄 全平台正文提取** —— 此前只有微信公众号返回正文，其余平台只取「第一行 / 截断 120 字」当标题。

- 现在抖音、小红书、微博（含头条文章）、X、B站、YouTube、TikTok、Instagram、公众号都返回完整正文。
- 正文上限 4000 → **20000 字**；标题压成一行、超 **50 字**截断补「…」；**正文与标题相同则置空**、纯符号内容置空。
- 重新解析不会把已有正文冲成空串（`upsert` 改为「有就更新、没有就保留」）。
- 真机回归 39 条：小红书 6/6、微信 6/6、B站 2/2、微博 9/11、抖音 8/9、X 10/13（未通过的均为「正文=标题」「仅文字无媒体」等既定行为）。

**🖼 「实况」页（底部导航第 3 项，位于历史与 MD5 之间）** —— 选一段视频（必选），可选配一张同画幅的图片，一键合成实况图。

- **不选图片也行**：自动从视频的**时长中点**抽一帧当封面 —— 与手机拍摄的实况一致取在中段，长按播放才有「从静图动起来」的过渡，而不是「直接播一段视频」。
- **选了图片就校验画幅**：比的是**宽高比**而不是像素尺寸。2160×3840 的图与 720×1280 的视频都是 9:16，可以配；比例不同才报错，并给出双方尺寸。
- **选实况图当封面也没问题**：会自动剥掉它尾部的视频，只取静态封面，不会把两段视频塞进一个文件。
- **命名** = 素材原名 + 保存时间（`1000669313_实况_20261024_111938.jpg`），前缀可改；重名成对加 ` (1)`；**原件全程不动**。
- 两种产出：默认「同名配对」（`x.jpg` + `x.mp4`），开关打开则生成「单文件动态照片」（视频内嵌进 jpg + XMP 声明，给小米 / OPPO / 华为那套用）。

**🧩 vivo 实况图双写** —— 拆开文件后发现，vivo 的实况信息写在**两个地方**：媒体库的 `live_photo` 字段，和 JPEG 尾部的一段私有数据（自拍写 566 字节，抖音 App 保存写 144 字节）。

- 此前只写字段：相册能播，但没有「动态照片 / 关闭动态照片」菜单，微信、抖音、小红书读文件时也认不出来。
- 现在两处都写、三处编号一致 —— **相册菜单回来了，微信、抖音、小红书也能识别**（真机验证）。
- 同时修掉一个隐蔽的错配：同一目录里十几张图被写成同一个编号，微信按编号找视频就全指到第一条（表现是「发出去的实况图都播合集第一张的动效」）。现在每对独立编号。

## 🔧 修复

- **抖音个别视频解析不出**：公开接口的 `aid` 渠道号各自服务不同的作品池，单渠道会静默漏掉。改为**双渠道并发、命中即返回**，实测漏解析的那条恢复正常，端到端还更快。
- **抖音失败原因不准**：此前只会说「15 秒内没能取到数据」。现在按三种判据分别给结论 —— 页面没加载完、接口连续回空（限流或未开放）、页面没发出详情请求（疑似改版）；作品被删除时直接提示，不再空等。
- **抖音图文被误判成实况**：判定条件由「任意一张带动效」改为「**每一张都带动效**」。
- **画质标签缺体积、三列顺序乱**：补上平台自报的 `data_size`，「平台默认档」标注移到体积之前，体积统一放最后一列。
- **合成时尺寸判断过严**：此前要求像素尺寸完全相同，把「同一画幅、不同清晰度」的正常组合也拦下了，改为比宽高比。
- **重选视频后缩略图不刷新**：缓存副本固定同名，界面以为没换过就直接跳过了重绘。改为按「重选次数」驱动。
- **解析超时收紧**：抖音兜底 12 秒、小红书 6.4 秒、微博 5.6 秒、外层上限 30 秒；yt-dlp 单次网络操作 10 秒、提取重试 1 次。以前失败要干等 75 秒。
- **Windows 端解析卡死**：yt-dlp 超时后 node 子进程仍握着管道，界面永远停在「正在调用解析引擎…」。现在超时杀整棵进程树，30 秒准时返回。

## 💡 改进

- **解析更快**：抖音短链只读第一跳（省 1~2 个 TLS 往返）+ 双渠道并发命中即返回，端到端 **2.9 秒 → 2.1~2.3 秒**。
- **提示文案按链路区分**：抖音「正在直接读取抖音作品数据…」、快手「正在间接读取…」、X「正在通过第三方解析服务…」、小红书 / 微博「正在打开内置浏览器…」—— 用户能看出慢在哪、走没走内嵌浏览器。
- **VPN 横幅不再误导**：只有「内置引擎」「第三方链路」才提示挂 VPN，走系统网络的浏览器链路不提示。
- **平台列表**补齐快手与公众号（解析能力早就有，主页漏列）。
- **快手品牌图标**用官方矢量（CC0，橙色 `#FF4906`），与 Windows 端同步。
- **快手两个显示问题**：竖屏视频按长边显示成「1920p」（改读平台自己的档位名）；同分辨率两条码率重复成两个「720p」（按档位名去重，保留高码率）。
- **Windows 网页端**按 P0~P3 对齐安卓：图集浏览、档位切换、浏览器兜底、MD5 页签，配套 63 个用例。

## 🔍 调研结论（本期不做）

- **知乎**：探针跑完，决定不做。想法 / zvideo 接口可用（纯 HTTP），但用户贴得最多的「回答」必须登录态（`need_login:403`）。知乎网页本身就能存图和复制正文，我们唯一能补的缺口只剩视频，投入产出不成立。
- **支付 SDK**：不写代码，方案与资质门槛单独成文（`docs/支付接入方案-调研与实施建议.md`）。

## ⚠️ 已知限制

- **微信朋友圈发实况仍会被降级成静态图**（提示「部分实况照片格式不标准」）。朋友圈的校验比聊天更严，目前没有找到它接受的确切结构；**聊天里发送是正常的**，动效也不会再串成第一张。
- **实况的第三方识别只在 vivo 上验证过**。小米 / OPPO / 华为 / 荣耀走的是另一套结构（单文件 Motion Photo，即页面上的「生成单文件动态照片」开关），按规范实现，**尚未真机实测**。
- **单文件模式在 vivo 相册不显示动态**：vivo 不读 XMP，这条路径本来就是给其他品牌准备的。
- **快手的实况图只有静态图**，动效拿不到（原因见上）。
- **知乎暂不支持**，链接会落到通用引擎并报 403。
- **抖音偶发「画面缩左上角」** 仍未复现（v1.0.6 起就没有稳定样本），如遇到欢迎反馈作品链接。
- **旧文件不会自动补 vivo 私有段**：需要重新下载或重新合成才会带上。
- 单张实况视频下载失败时只写日志，界面上不单独提示（表现为该张不是实况）。
- Windows 网页端暂不做实况合成页（解析实况图时照常下成一图 + 一段同名视频，不承诺相簿可动）。

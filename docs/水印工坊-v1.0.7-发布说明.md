# 🎬 水印工坊 v1.0.7 —— 快手入列，实况图可以自己做了

> 安装包见下方 Assets：`shuiyin-gongfang-v1.0.7.apk`

这一版有两件事：**快手正式支持**，以及一个全新的**「实况」页** —— 手里现成的图片和视频，现在能自己合成实况图；下载下来的实况图，也终于能在 vivo 相册里出现完整的「动态照片」菜单，并让微信、抖音、小红书认出它是实况。

## ✨ 新增

**⚡ 快手** —— 视频与图集支持，走移动端页面直读，不需要登录、不需要签名。实况图的动效在页面数据里没有对应字段，因此**只拿到静态图**，这一点如实标注，不假装支持。

**🖼 「实况」页（底部导航第 3 项）** —— 选一段视频（必选），可选配一张同画幅的图片，一键合成实况图。

- **不选图片也行**：会自动从视频的**时长中点**抽一帧当封面 —— 和手机拍摄的实况一样取在中段，长按播放时才有「从静图动起来」的过渡，而不是「直接播一段视频」。
- **选了图片就校验画幅**：比的是宽高比而不是像素尺寸。2160×3840 的图和 720×1280 的视频都是 9:16，可以配；比例不同才报错，并给出双方尺寸。
- **选实况图当封面也没问题**：会自动剥掉它尾部的视频，只取静态封面，不会把两段视频塞进一个文件。
- **命名**：默认取素材原名 + 保存时间（`1000669313_实况_20261024_111938.jpg`），前缀可改；重名成对加 ` (1)`。
- **原件全程不动**，成品另存到下载目录，产物可以直接「查看合成结果」交给系统相册。

**🧩 vivo 实况图双写** —— 实测发现 vivo 的实况信息是写在**两个地方**的：媒体库里的 `live_photo` 字段，和 JPEG 尾部的一段私有数据。此前只写了字段，所以相册能播、但没有「动态照片 / 关闭动态照片」菜单，微信和抖音读文件时也认不出来。现在两处都写，三处编号保持一致。

## 🔧 修复

- **微信群发实况图，播的总是合集第一张的动效**：同一目录里十几张图被写成了同一个配对编号，微信按编号找视频就全指到了第一条。现在每一对独立编号（真机复验：图片与视频一一对应）。
- **重选视频后缩略图不刷新**：缓存副本固定同名，界面以为没换过就直接跳过了重绘。改为按「重选次数」驱动，重选即重抽。
- **合成时图片尺寸判断过严**：此前要求像素尺寸完全相同，把「同一画幅、不同清晰度」的正常组合也拦下了。
- **抖音失败原因更准**：分为「页面没加载完 / 接口连续回空（限流或未开放）/ 页面没发出详情请求（疑似改版）」三种，各自给一句结论，不再罗列可能性。
- **解析超时不再空等**：抖音兜底 12 秒、小红书 6.4 秒、微博 5.6 秒、外层 30 秒；yt-dlp 单次网络操作 10 秒、提取重试 1 次。

## 💡 改进

- **解析更快**：抖音短链只读第一跳（省 1~2 个 TLS 往返），双渠道号并发、命中即返回，端到端从 2.9 秒降到 2.1~2.3 秒。
- **提示文案按链路区分**：抖音「正在直接读取抖音作品数据…」、快手「正在间接读取…」、小红书 / 微博「正在打开内置浏览器…」，用户能看出慢在哪。
- **平台列表**补齐快手与公众号。
- **正文上限** 4000 → 20000 字，标题超 50 字截断，正文与标题重复时置空。
- **Windows 网页端**按 P0~P3 对齐安卓：图集、档位、浏览器兜底、MD5 页签，配套 63 个用例；并修掉解析超时后 node 子进程占住管道导致的界面卡死。

## ⚠️ 已知限制

- **微信朋友圈发实况仍会被降级成静态图**（提示「部分实况照片格式不标准」）。微信朋友圈的校验比聊天更严，目前没有找到它接受的确切结构；**聊天里发送是正常的**，动效也不会再串成第一张。
- **实况图的第三方识别只在 vivo 上验证过**。小米 / OPPO / 华为 / 荣耀走的是另一套结构（单文件 Motion Photo，即页面上的「生成单文件动态照片」开关），按规范实现，**尚未真机实测**。
- **单文件模式在 vivo 相册不显示动态**：vivo 不读 XMP，这条路径本来就是给其他品牌准备的。
- **快手的实况图只有静态图**，动效拿不到。
- **旧文件不会自动补 vivo 私有段**：需要重新下载或重新合成才会带上。
- 单张实况视频下载失败时只写日志，界面上不单独提示（表现为该张不是实况）。
- Windows 网页端暂不做实况合成页（产品决定：解析实况图时照常下成一图 + 一段同名视频，不承诺相簿可动）。

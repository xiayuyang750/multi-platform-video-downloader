# 水印工坊

**一个真正开箱即用的多平台内容解析下载工具 —— Android 原生客户端 + Windows 本地 Web 端**

视频、图文、图集、实况图都能拿，**还能改 MD5**（视频与图片，另存副本、原件一字不动）；内置 Python 运行时、ffmpeg 与 JS 引擎，装完就能用，不需要装任何环境

## 它解决什么问题

市面上的同类工具，要么是**套壳网页**（体验割裂、广告多），要么**装完还要自己配环境**（Python、ffmpeg、Node 一个个装）。这个项目的做法不同：

> **把一个完整的解析引擎塞进 APK 里。**

Python 3.12 运行时、ffmpeg、QuickJS 全部随包分发，其中 ffmpeg 和 QuickJS 都是**本项目用 NDK 自己交叉编译**的（不是从第三方下载的预编译二进制）。用户装完打开即用。

## 核心亮点

### 1. 下载后直接在应用内播放 —— 解决一个行业难题

实测发现：**YouTube 的 53 个可用格式里，0 个是音视频合一的**；B站 也全是 `audio only` + `video only`。主流平台已全面 DASH 化，"拿直链直接播"这条路对它们根本走不通。

所以本项目的做法是：**下载时用 ffmpeg 把双轨合流成单文件，并把产物路径记进历史库**，之后点开历史记录就能直接看已下载的文件。

这是网页端做不到的 —— 网页只能播在线直链，而这两家已经不存在可播直链了。

### 2. 系统分享直达

在 B站 / 抖音 / YouTube 客户端里点「分享 → 视频解析下载」，链接自动填入并开始解析。省掉"复制 → 切应用 → 粘贴"三步。

（分享出来的文本常带前后缀，如 `【标题】 https://…`，所以做了 URL 提取并剥掉尾部中英文标点。）

### 3. 抖音无水印 —— 公开接口直取，浏览器模式兜底

这条路换过两次，过程本身值得记：

**第一版：让 WebView 去当那个浏览器。** 抖音的接口要 `a_bogus` 签名和登录态，纯 HTTP 客户端两样都拿不到，必然 403。所以让 WebView 自己算好签名、带上登录态，我们只在它请求 `aweme/detail` 时拦下响应。

> 踩坑记录：这里必须用**桌面版 UA**。移动版 UA 会让链接跳到 `iesdouyin.com` 分享页，数据是服务端直出在 HTML 里的，全程不触发接口 —— 拦截器永远等不到东西。

**第二版（现行）：找到了一条不用签名的公开接口。** 从一份参考实现的 dex 里提取字符串时发现，抖音有一个不需要签名、也不需要登录的接口，只要把 UA 伪装成抖音 App 自己：

```
https://aweme.snssdk.com/aweme/v1/feed/?aweme_id=<作品ID>
```

直连即 200、秒回，返回的 `aweme_list` 里标题 / 作者 / 直链 / 码率档位齐全。于是它成为**主路径**，原先的浏览器方案退居**兜底**：

| | 主路径 | 兜底 |
|---|---|---|
| 安卓端 | 公开接口（纯 HTTP） | WebView 拦截 + 原生请求重放 |
| Windows 端 | 公开接口（纯 HTTP） | DrissionPage 驱动本机浏览器监听 |

两端平时都不再需要浏览器，也不再需要 Cookie。

> 另外两个坑：① 这个接口会**顺带返回一串相关推荐**（实测 7 条），必须按作品 ID 挑出目标，不能直接取第一条 —— 第一条恰好是目标只是运气好。② 它下发的直链域名是 `365yg.com` / `amemv.com`，**不是** `douyinvod.com`，而早期代码是按 `douyinvod.com` 判断「这是裸直链」的，导致下载文件名退化成 URL 片段（静默失效，不报错）。详见 `docs/抖音直链CDN域名判断修复.md`。

### 4. 图文 / 图集 / 实况图 —— 不止视频

「解析下载工具」默认只处理视频，因为图文类内容在各家都是**另一套数据结构**。本项目把这条路也走通了，而且走的是**不登录、不签名**的公开路径：

| 平台 | 支持的内容形态 |
|---|---|
| **抖音** | 图文、图集（最多 35 张）、**实况图** |
| **X** | 单图、图集、**一条推文里的多个视频**、图文混排 |

**实况图是真的「会动」。** 抖音服务端把它拆成两样存：一张静态图 + 一段 1~5 秒的短视频，那段短视频**自带音轨** —— 就是你在抖音里听到的「这张图自己的声音」。本项目的做法是：

- **浏览时**：滑到哪张就自动播放哪张的动效（静态图先垫在底下，动效渲染出来后再叠上去，所以不会先黑一下）
- **下载时**：图片与视频**同名配对**落盘，再往系统相册库里补上该品牌的「动态照片」标记 —— 相册就会把它当成一张会动的照片，而不是"一张图 + 一个视频"

> 关于跨设备：各品牌的动态照片字段名并不统一（目前**已在一台 vivo 上真机验证通过**，其他品牌不保证相册能识别）。但图片与视频**两个文件一定完整保留**，任何手机都能正常查看与播放 —— 认成动图是加分项，认不出也不丢内容。

**X 那条链路为什么改成「第三方优先」**：原先是「yt-dlp 先跑，失败了才找第三方」，但 yt-dlp 对 X **是能跑通的**（拿到一条视频就返回），于是多视频 / 图文混排**永远轮不到**第三方；纯图片更是被判成「这条推文里没有视频」。改过来之后，一条推文里的图、视频、混排内容一次全部拿齐，而且拿到的是**可直接播放的直链**（yt-dlp 给的常是音视频分轨，界面上播不了）。

**文案上的一个克制作法**：纯文字、投票、这类推文**本身就没有媒体文件**，换链路、补 Cookie 都不会有用。所以这种情况会**单独给一句明确的结论**，不再顺势提示「请检查 Cookie」—— 那会把用户引到完全错误的方向上。

### 5. 两端同一套视觉骨架，安卓端独立演进

配色、圆角、间距、字号源自同一份设计令牌，Windows 网页端与 Android 客户端看起来仍是**同一个产品**：安卓端按平台习惯改成底部导航（而非网页端的侧边栏）。

v1.0.3 起安卓端在这套骨架上加了独立的一层品牌表达 —— 品牌渐变（色值取自启动图标）、卡片投影、页面与列表的转场动效。这些是安卓端独有的，网页端保持原样。两边的关系从「同一套令牌」变成了「同一套骨架、各自长肉」。

### 6. 应用内反馈，且不把凭据塞进 APK

「设置 → 意见反馈」可以直接填问题、传截图、留联系方式，一键送到开发者手上。走的是企业微信的群机器人接口。

这里有个刻意的选择值得说明：**最常见做法是让 App 直接用 SMTP 发信，但那样邮箱授权码就必须硬编码进客户端**，而本仓库是公开的 —— 授权码等于挂在网上，谁拿到都能冒充你发信、还能读你的全部邮件。群机器人的 webhook 性质完全不同：它泄露了最多是别人往群里发消息，把机器人移出群就当场作废，不存在可被冒用的身份。

顺带解决了可达性：接口是腾讯自己的域名，国内不挂代理也能连通 —— 而本项目的用户里有大量抖音/B站用户，他们恰恰是不开代理的，反馈通道不能用境外服务。

### 7. 改 MD5 —— 不是往文件尾巴上怼几个字节，而是写进容器自己的元数据位

同一份内容被判成「已经有人传过」，多半是 MD5 撞了。这个功能没有做成一个「点一下按钮」的黑盒，而是**一条能走完的流程**：从相册里挑一份视频或图片 → 看它的时长 / 大小 / 分辨率 / 原指纹 → 改 → 预览确认真能播 → 另存到下载目录。四步，每一步都看得见。

- **两条改写路径，都保住了「文件仍然完全规范」**。视频走 ffmpeg **无损重封装**（`-c copy` + 往 comment 元数据里写随机串）—— 不重编码、画质零损失，产物仍是标准 mp4，音视频流与时长完好；图片走**容器自带的元数据位** —— PNG 在 IHDR 之后插一个标准 `tEXt` 块、JPEG 插一个标准 `COM` 注释段，成品丢给 ffmpeg 做完整解码是**零告警**、画面尺寸不变。
   > 为什么图片不能沿用视频那条路：实测 `ffmpeg -c copy -metadata comment=…` 对 jpg / png / webp 产出的字节与原件**逐字节相同**（这些容器里没有 moov-udta 那样可写的元数据区），MD5 根本没变。
- **原件一字不动**。挑中的媒体先整份复制进应用缓存，改写只碰这份副本，保存时在下载目录另存一份新文件并让相册收录 —— 真机上用 `md5sum` 逐字核对过：成品的指纹与界面上显示的新值一致，原文件的指纹与改写前一致。
- **「作废」是看得见的**：改过的那两行，旧值用淡色 + **红色删除线穿过字心**，新值就排在它后面（大小同一行、MD5 另起一行）—— 一眼分得清哪份作废、新的是哪份。
- **硬性权限门**：点「选择视频 / 选择图片 / 保存文件」前先查「文件管理权限」（Android 11 起叫「所有文件访问权限」），没授权就弹窗说明并引导去系统设置页，绝不静默通过 —— 缺这个权限时产物只能落到应用私有目录，文件管理器里根本找不到，用户会以为存丢了。
- 入口走**系统相册选择器**（视频一个、图片一个，各自只限定一种媒体类型），自带「顶部分组、按相册文件夹切换」；没有退回到文件管理器式的目录浏览器。

```
│      └── WebView                 抖音浏览器模式兜底                   │
│      │                                                               │
│  ────┼──────────────────────  ← Kotlin / Python 边界 ────────────────│
│      │                                                               │
│  Chaquopy 内嵌 CPython 3.12                                          │
│      │                                                               │
│      ├── yt-dlp                  解析 / 下载（进程内 Python API 调用） │
│      ├── ffmpeg（自编译）         音视频合流                           │
│      ├── QuickJS-NG（自编译）     YouTube n-sig 挑战求解               │
│      └── SQLite                  解析历史                            │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 为什么是"进程内调用"而不是子进程

Chaquopy 里的 CPython **不是可执行文件**，没有 `python` 可 fork；而且实测 Android 上 fork 出的子进程偶发 `SIGSEGV`（`_posixsubprocess` 层面的已知竞态）。所以 yt-dlp 的调用方式从"拼命令行 + subprocess"改成了**直接调 Python API**。

这个改动带来一个意外好处：下载完成后不需要像命令行版那样靠 `--print after_move` 回传文件路径，直接读 `info` 对象即可。

### 为什么原生二进制要自己编

ffmpeg 和 QuickJS 都是**本项目用 NDK r30 交叉编译**的（脚本见 `android/tools/`）：

- **ffmpeg 9.0.2**，LGPL 2.1，静态链接。只出 `ffmpeg` 一个程序，不带 ffprobe / ffplay —— 静态链接下每多一个程序就多一整份 libav* 代码。
- **QuickJS-NG 0.17.0**，剥掉调试符号后从 6.64 MB 降到 1.21 MB。

不用第三方预编译二进制的理由很直接：**那是一个会带着完整文件读写和网络能力、装进用户手机的可执行文件，来源不可追溯就不该进最终产物。**

两个 `.so` 的 LOAD 段都按 `0x4000` 对齐，4 KB 页与 16 KB 页设备通用。

## 踩过的坑（部分）

这些是真实调试出来的结论，写在这里省得后来者重走：

| 问题 | 原因与解法 |
|---|---|
| Gradle 报 `InternalProblems` 不存在 | Gradle 9.6+ 移除了 AGP 8.x 依赖的内部 API，本项目必须用 AGP 9.x |
| AGP 9 下 `org.jetbrains.kotlin.android` 报错 | AGP 9.0 起内置 Kotlin 支持，不能再显式声明该插件 |
| 开了 Compose 却报缺编译器 | AGP 9 内置 Kotlin，但**不含** Compose 编译器，仍需声明 `org.jetbrains.kotlin.plugin.compose` |
| `Module was compiled with an incompatible version of Kotlin` | Coil3 是 Kotlin Multiplatform 库，会带进 `kotlin-stdlib 2.4.x` 与 JetBrains 版 Compose，与 androidx 体系冲突。改用 Coil2 |
| 封面图不显示 | B站封面是 `http://`，Android 9+ 默认禁止明文流量，需开 `usesCleartextTraffic` |
| 下载成功但拿不到文件路径 | 顶层 `info` 上**没有** `filepath` 键，路径挂在 `requested_downloads` 上 |
| 中文标题下载失败 | `trim_file_name` 按字符算，而 Android 文件系统限制是 **255 字节**（一个汉字 3 字节）。改为按字节截断 |
| `adb input text` 输入变成了中文乱码 | 设备上的中文输入法会把 ASCII 当拼音转换。改用 `am start` 发分享意图喂链接 |
| Gradle 依赖解析总是超时 | JVM 不读系统代理，而本机是 TUN 模式代理，需在 `gradle.properties` 显式配 `systemProp.https.proxyHost` |
| 装个新包后「所有文件访问权限」又变回未授权 | `adb install -r` 覆盖安装会把 `MANAGE_EXTERNAL_STORAGE` 的 appop 重置回 deny（本机 Android 16 实测复现两次）。表现是「明明刚授权过，装完新版本解析页又弹出授权引导」—— 这是 Android 对这类敏感权限的处理，不是引导逻辑坏了。测试时容易误判 |
| 反馈里的图片一张都发不出去 | `inJustDecodeBounds = true` 时 `BitmapFactory.decodeStream` **按设计返回 null**（它只负责往 `Options` 填宽高）。原代码写成 `openInputStream(uri)?.use { decodeStream(...) } ?: return null`，于是每次都当成"读取失败"，压缩函数无条件返回 null |
| 播放器的进度条点不到 | Media3 的控制器贴在 PlayerView 底部，而竖屏视频按真实比例算出的高度很长，播放器下边缘会落到应用底部导航栏后面，进度条正好被盖住。给播放区加了「不超过屏高 40%」的上限 |
| 历史列表里解析时间从来不显示 | 算过宽度：行内可用约 1085px，平台图标 + 三个操作图标 + 间隙就吃掉约 630px，再塞一个 `2026-10-01 10:06`（约 310px），标题只剩 5 个字。改成时间单独占一行 |

## 快速开始

### 直接用现成包（不需要任何构建环境）

仓库里就带了打包好的安装包：

- **[`releases/水印工坊-1.0.5.apk`](releases/水印工坊-1.0.5.apk)** —— arm64-v8a，`versionCode 5`，Android 8.0（API 26）及以上

### 从源码构建

#### 环境要求

- JDK 17+
- Android SDK（platform 37、build-tools 36.0.0）
- NDK r30（仅重建原生二进制时需要）
- Python 3.12（构建期供 Chaquopy 打包用）

#### 构建

```bash
# 1. 编译原生二进制（首次或需要更新时执行，产物在 jniLibs/）
"$GIT_BASH" android/tools/build-ffmpeg.sh
"$GIT_BASH" android/tools/build-quickjs.sh

# 2. 构建 APK
gradle -p android assembleDebug

# 3. 安装到设备
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

> 两个原生库体积较大，未纳入版本控制，由脚本生成。

## 设计取舍记录

**保存位置为什么不能随便选**
Android 的 SAF 给的是 `content://` URI，而 yt-dlp 走普通文件 API 读不了。所以只能"系统下载目录 / 应用私有目录"二选一，优先前者，无权限时自动回退并在界面上如实说明。

**为什么不自动播放**
自动起播会立刻拉一个几百 MB 的连接，而用户可能只想下载。

**解析为什么不能取消**
进程内调用没有子进程可 kill，界面的"取消"只能做到"我不等了"，Python 侧会自己跑完。所以界面自己收 75 秒超时（与 Windows 端一致）。

**纯音频为什么不能在线播（v1.0.3 记录，暂未处理）**
可播地址的筛选规则是「音视频必须同时存在」—— `_pick_playable_url` 会同时排除 `vcodec == "none"`（纯音频）和 `acodec == "none"`（纯视频），一个候选都不剩时直接返回空字符串。于是纯音频源解析完拿不到在线地址，界面上还会说「该站点解析出的是音视频分离的流…需下载后才能播放」—— 那句话对音频其实不准确：音频不是「分轨」，是本来就没有视频轨。
**下载之后是能播的**：`playSource` 里「本地文件」那条分支优先于在线直链，而且不检查类型，音频文件会直接交给 ExoPlayer。
要补齐得做两件事：① 筛选规则给纯音频放行（没候选时退一步）；② 播放区按 `playKind` 换形态 —— 纯音频的 `VideoSize` 是 `0×0`，现在的播放器会留一个**大黑方块**在放声音。暂缓的原因：手上没有纯音频链接可实测。

**外观偏好为什么不放进引擎的 Settings**
项目的设置（保存位置、Cookie）都走 Python 侧，唯独外观用了 Android 的 SharedPreferences。理由是：外观是纯 UI 偏好，引擎没有任何理由知道它。为了取一个颜色选择走一趟 Chaquopy 往返，既慢、又把 UI 和引擎耦在一起。这是全项目唯一一处 SharedPreferences，只存这一件事。

**改 MD5 为什么「另存副本」而不是原地改**
原地改有两个硬伤：① 相册 / 文件选择器给的是 `content://`，既不能原地回写、授权又只在本次会话内有效；② 用户的原文件一旦被改坏就再也回不去。所以挑中的媒体先整份复制进应用缓存，改写只碰这份副本，保存时在下载目录另存一份新文件 —— 原件全程只读，真机上用 `md5sum` 逐字核对过。

**图片改 MD5 为什么不沿用 ffmpeg 那条路**
实测 `ffmpeg -c copy -metadata comment=…` 对 jpg / png / webp 产出的字节与原件**逐字节相同**（这些容器没有 moov-udta 那样可写的元数据区），MD5 根本没变。改成往容器自带的元数据位里写：PNG 在 IHDR 之后插标准 `tEXt` 块、JPEG 在 SOI（有 APP0 就排在它后面）之后插标准 `COM` 段。两条路都踩过坑 —— 比如把 `tEXt` 放到 IDAT 之后，ffmpeg 会直接报 `chunk too big` 判解码失败（`Length` 字段只算数据那一段、而 CRC 覆盖「类型 + 数据」，这两个规则不一样，混了就会被解析器读串）。

**历史的平台标签为什么按条数排**
标签原来按平台名的字符串顺序（Kotlin 的 `sorted()` 走 Unicode 码位）排。中文名一律排在拉丁名之后，于是「其他」(U+5176) 恰好压在「抖音」(U+6296) 前面 —— 「其他」一常驻，抖音就被顶到了最后一位。现在改成按记录条数从多到少排（条数相同按平台名），并把「其他」这个兜底桶固定垫底。

**修复**

- **设置页会显示过期的保存位置。** 引擎只在启动时挑一次输出目录并缓存住，而能不能写进系统「下载」目录完全取决于存储权限。于是出现这个假象：先开应用（未授权 → 落到私有目录）→ 再去系统设置里授权 → 回到设置页**仍然显示私有目录**，可界面上写着「授权后会自动改回去」。现在改成每次读设置都重新探测一次（探测方式是**真往候选目录写一个空文件再删掉**，不是猜）。
- **导入的 Cookie 对 TikTok 完全不生效。** `defaults.json` 的 `platform_rules` 里根本没有 tiktok 这一项，`use_cookies` 取不到值，于是带 Cookie 的分支压根不会走到 TikTok —— 而界面上却把它当成「需要 Cookie 的平台」在说。补上了这一项。**注意：尚未在真机上实测**，能否访问还取决于所在地区。

**文案与信息**

- 解析页的平台列表末尾补上「等」：实际能认哪些站点由底层的 yt-dlp 决定，写死六个不属实。
- 设置页删掉了一批评注式说明 —— 「外观」下面那条、「版本更新」下面那条，以及「保存位置」在正常情况下的解释（解析页的授权引导已经说过这件事，只有真回退到私有目录时才再解释原因）。
- 「遇到问题」和反馈页不再只谈报错：功能建议、体验问题、想加什么，都明确写了可以提。
- 「关于」卡片改为如实列全：解析下载是 yt-dlp，音视频合流是自编译 ffmpeg，YouTube 画质靠自编译 QuickJS，抖音走内置浏览器模式，X 在官方接口失效时走备用链路 —— 原来只说「由 yt-dlp 完成」，既不准确，也让用户遇到问题时不知道该往哪个方向想。
- 「关于」补上**支持范围**：图文 / 实况图 / 图集这类内容的平台链接，解析功能正在开发中；目前只支持视频和音频。这条以前哪都没写，用户拿图集链接来试只会一头雾水。
- 邮件反馈补上提醒：**记得备注主题或来意**，否则只看到一个邮箱地址，看不出你想说什么。

**移除**

- 设置页的「打开引擎自检页」入口删掉了。它是调试页，一进去就**自动跑三条网络解析**，用户看到一屏原始 JSON 只会以为应用卡死或偷跑流量。
  页面本身保留，改为 `exported="true"`，用 `adb shell am start -n com.ytdlp.android/.ProbeActivity` 打开。顺带修掉清单里那句一直没验证过的注释 —— 原本写着「只能用 adb 启动」，但 `exported="false"` 时 adb 会被 `SecurityException` 直接拒绝，两条路其实都走不通。

**其他**

- 历史详情里的「原始链接」默认折成 2 行、点一下展开，**末尾带一个箭头图标**。B站分享链接带着一串跟踪参数（`buvid` / `spmid` / `share_session_id`…），完整铺出来实测有 14 行、742px，占掉四分之一屏。
  箭头不是装饰：第一版只靠文本末尾的「…」，实机反馈是**没人意识到这里能点开** —— 省略号只表示「被截断了」，不表示「可展开」。
- 应用名统一为「水印工坊」。此前 README 里叫「多平台视频下载器」，和桌面图标名对不上。
